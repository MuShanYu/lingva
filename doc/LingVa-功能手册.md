# LingVa 功能手册

*内部参考版 · Feature Manual v1.0.0*

LingVa 是一个 Manifest V3 的 Chrome 翻译扩展：一次划词、一次整页翻译、一段双语字幕、一份 PDF 对照阅读，背后是同一套多引擎调度与本地存储。本手册逐页拆解它目前真正具备的能力、参数与边界，供产品资料撰写与验收对照使用。

| 形态 | 入口 | 数据去向 | 界面语言 |
| --- | --- | --- | --- |
| Chrome 扩展 · Manifest V3 | 弹窗 / 划词 / 悬浮球 / 独立设置页 / PDF 阅读器 | 仅本机 IndexedDB + chrome.storage，无自建后端 | 简体中文 / English |

基于 easy-translate 仓库当前源码逐项核实整理，标注版本号与算法参数均取自代码常量。

## 00 产品总览

LingVa 把"翻译"拆成六个真实会用到的场景，用同一套引擎调度层串起来，而不是六个互相独立的功能开关。

核心架构上，任何一次翻译——无论发起自弹窗、划词面板、整页翻译、视频字幕还是 PDF 阅读器——都会汇聚到唯一一条链路：内容脚本或设置页通过 `chrome.runtime.sendMessage` 把请求交给后台 Service Worker，Service Worker 转发给常驻的 Offscreen 文档（MV3 下真正发起网络请求的地方），Offscreen 再按引擎 id 路由到已注册的 Provider。新增一个引擎只需要实现一次 `translateBatch(credentials, texts, from, to, ctx?)` 并注册一行，调度层不需要为它写任何 if/else 分支。

- **六个入口，一套引擎** —— 弹窗、划词面板、悬浮球整页翻译、PDF/文档阅读器、视频双语字幕、多引擎对比，共享同一个 Provider 注册表与用量统计口径。
- **本地优先** —— 翻译历史、生词本、用量统计三张表全部落在浏览器本机 IndexedDB，扩展本身不设后端服务器，也不中转任何翻译请求内容。
- **可插拔的 AI 服务商** —— 除四个传统机翻引擎外，任意 OpenAI 兼容的大模型服务都能作为翻译引擎接入，价格、模型目录、系统提示词均可在设置页自定义。
- **面向学习而非只是查词** —— 划词命中词典即展示音标、释义、例句，可一键收进生词本，并配一套简化版 SM-2 间隔重复算法安排复习节奏。

## 01 翻译引擎与 AI 服务商

四个传统机翻引擎负责"又快又稳"，OpenRouter 与任意 OpenAI 兼容端点负责"又准又可控"，两条路线在同一个下拉框里并列出现。

### 传统机翻引擎

设置页「引擎与翻译」的机器翻译分组固定为四个卡片。此前接入过的百度翻译、有道翻译已在近期版本中彻底移除，不再出现在任何引擎列表里。

| 引擎 | 端点 | 所需凭证 | 批量方式 |
| --- | --- | --- | --- |
| **内置翻译**（`google-free`） | `translate.googleapis.com/translate_a/single` | 免配置 | 不支持官方批量协议，内部用并发单条请求模拟 |
| **DeepL** | `api-free.deepl.com` / `api.deepl.com`（按 Key 是否以 `:fx` 结尾自动判定 Free / Pro） | DeepL API Key | 原生数组批量 |
| **Google 翻译** | Google Cloud Translation v2 | Google API Key | 原生数组批量 |
| **Microsoft 翻译** | `api.cognitive.microsofttranslator.com` | 订阅密钥 + 区域（如 `eastasia`） | 原生批量，单批上限 100 条 / 5 万字符 |

每张引擎卡片都带「测试连接」按钮，可直接查看请求延迟（毫秒），无需离开设置页验证密钥是否有效。

### OpenRouter 聚合平台

OpenRouter 作为独立分组接入，默认地址 `https://openrouter.ai/api/v1`（可替换为自建代理）。请求体附带 `usage:{include:true}`，因此每次翻译都能拿到 OpenRouter 返回的真实美元成本，无需本地估算。

- **模型目录自动同步** —— 拉取 OpenRouter 公开的 `/models` 接口并自动分页，仅保留输出模态包含文本的模型，单个模型价格与是否下线可随时刷新。
- **按厂商分组选择器** —— 模型选择面板左侧按厂商分组，免费模型单独置顶；每张卡片展示上下文长度、输入 / 输出单价、免费标签、即将下线提醒、推理与工具调用能力标签。
- **可选思考过程** —— 对支持推理的模型，可开启 `reasoning.effort`（低 / 中 / 高），关闭时不发送该字段，避免不支持的模型报错。
- **搜索与多选** —— 支持按 id / 名称 / 描述模糊搜索；多选模型后点击「确认」才会落盘，直接关闭面板不会保存改动。

### OpenAI 兼容自定义端点 `近期优化`

除 OpenRouter 外，LingVa 内置五个开箱即用的 OpenAI 兼容服务商预设，且允许用户按需新增任意数量的自定义端点——两者共用同一套请求 / 响应解析逻辑，新增一个服务商不需要写新代码。

| 服务商 | 默认端点 | 预置模型示例 |
| --- | --- | --- |
| **DeepSeek** | `api.deepseek.com` | `deepseek-v4-flash` / `deepseek-v4-pro` |
| **Google Gemini** | `generativelanguage.googleapis.com/v1beta/openai` | `gemini-3.7-flash` / `gemini-3.1-pro-preview` |
| **Grok（xAI）** | `api.x.ai/v1` | `grok-4.6` / `grok-4.3` |
| **GLM（智谱）** | `open.bigmodel.cn/api/paas/v4` | `glm-5.3` / `glm-4.5-air` |
| **Qwen（阿里云）** | `dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.8-flash` / `qwen3.8-max` |
| **自定义** | 用户自行填写 | 用户自行填写，可无限新增实例 |

每个模型都能单独设置输入 / 输出单价（美元 / 百万 token）用于本地估算花费；若用户手动改过某个模型的价格，插件升级更新预设价格时不会覆盖用户的改动，只有未被改动过的模型会自动跟随新预设价。模型目录同样支持从服务商的 `/models` 接口拉取，拉取失败时可直接手填模型名称兜底。

### 批量与容错机制

所有大模型类引擎不用 JSON 作为输出格式——含引号、换行的翻译文本极易让模型输出破损的 JSON——而是要求模型按 `###<序号>###` 哨兵标记分隔每一条译文，纯文本更稳健。

| 项目 | 说明 |
| --- | --- |
| max_tokens 估算 | 批次总字符数 ÷ 2.5 + 每条 20 token 开销 + 200 余量，上限 32768 |
| 请求超时 | 60 秒，超时自动中止 |
| 解析失败时 | 二分重试：批次一分为二分别重发，逐步缩小问题范围到具体某一条文本 |

### 共享模型参数

温度（默认 0.1，可视化滑杆调节）与系统提示词模板对所有大模型引擎生效，不需要为每个服务商单独配置；系统提示词支持 `{target_language}` 占位符，可编辑保存，也可一键恢复默认文案。

## 02 浏览器弹窗

400×600 的固定尺寸弹窗，翻译、历史记录、生词本三个标签页始终保持挂载，只切换显示，避免重复触发剪贴板读取之类的副作用。

### 翻译

- **输入即译** —— 停止输入 600ms 后自动发起翻译，单次最多 512 字符；源 / 目标语言可一键互换（源语言为「自动检测」时禁用互换）。
- **剪贴板检测** —— 弹窗打开时检测一次剪贴板（非持续轮询），内容与上次不同则弹出「粘贴翻译」提示条，可在设置页整体关闭。
- **结果操作** —— 朗读、复制（1 秒内切换成功图标反馈）、重新翻译、展开到底部抽屉查看完整译文。
- **会话记忆** —— 语言对、输入内容、上次译文与所选引擎均持久化，下次打开弹窗自动恢复上一次的状态。

> **多引擎对比翻译**
> 勾选多个引擎或模型后，LingVa 会依次调用每一个引擎完成翻译（当前主引擎作为基准，强制勾选且不可取消），结果以标签形式切换查看，并对每条译文与基准译文做差异高亮，方便直接看出哪个引擎多译、少译或译法不同。

### 历史记录

支持原文 / 译文模糊搜索，以及「全部 / 已收藏」筛选；每条记录展示语言对、相对时间、来源引擎与收藏星标，点击可展开完整详情抽屉。列表底部显示总条数，并提供二次确认的「清空历史」。

### 生词本与间隔复习

生词本按状态分六类筛选：全部、新词、学习中、复习中、已掌握、已暂停。每条生词展示美 / 英双音标（发音图标可跟读）、词性、译文、释义与命中原词高亮的例句，支持暂停 / 恢复与删除。

**复习状态流转**

| 状态 | 说明 |
| --- | --- |
| 新词 new | 刚收藏，尚未进入复习队列 |
| 学习中 | 掌握等级为 0，需要频繁复习 |
| 复习中 | 掌握等级 1–4，按间隔天数排队复习 |
| 已掌握 | 掌握等级达到 5 星，不再进入复习队列 |
| 已暂停 | 用户手动暂停，排除在复习之外 |

算法为简化版 SM-2（并非 Anki 完整实现），核心参数与公式：

| 项目 | 公式 / 数值 |
| --- | --- |
| 初始易记因子 | 2.5 |
| 答「认识」 | 间隔天数 = 首次记为 1，此后 = 上次间隔 × 易记因子（四舍五入）；易记因子 +0.1（上限 2.8）；掌握等级 +1（上限 5） |
| 答「不认识」 | 间隔天数重置为 1；易记因子 −0.2（下限 1.3）；掌握等级 −1（下限 0） |
| 下次复习时间 | 当前时间 + 间隔天数 × 24 小时 |
| 每日复习队列上限 | 20 条，按到期时间升序排列 |

复习面板（抽屉）打开时会锁定当次的待复习队列快照，答题后立即应用到该生词的 SRS 状态；系统会用编辑距离检测「易混淆词」——若队列里存在形近词，会在反馈后插入并排的辨析卡片对比两者。复习完成后展示总结页：复习总数、认识 / 不认识次数、连续打卡天数，刷新历史最佳会有专门的金色标签提示。

设置页可开启「每日复习提醒」并指定提醒时间，基于 `chrome.alarms` + 系统通知实现，修改设置后立即重新校准闹钟。

## 03 划词翻译与悬浮球

两个入口共用一套页面内组件体系，都以 Shadow DOM 挂载，不污染宿主页面样式。

### 划词翻译面板

在任意网页选中文字（鼠标或键盘选区，300ms 防抖）即弹出翻译入口。面板会先判断输入类型：数字、URL、邮箱、emoji 等无语言学意义的内容直接过滤；判断为单词或短语时优先查询词典（Free Dictionary API），命中则展示词典卡片——音标（美 / 英）、词性、释义、命中原词高亮的例句，并可一键加入或移出生词本；未命中词典或判断为整句时，自动退化为整句翻译。面板支持拖拽、「钉住」防止点击外部关闭、朗读与复制，可在设置页整体关闭划词翻译。

### 悬浮球整页翻译

页面角落的圆形按钮，支持拖拽并自动吸附边缘，位置会被记住。点击展开菜单：未翻译状态可发起「翻译当前网页」（选择目标语言与引擎后开始，过程为表单 → 进度 → 结果三阶段）；已翻译状态可在原文 / 译文之间切换、重新翻译或退出翻译，翻译完成后悬浮球右上角会出现完成角标。

### 悬浮球设置 `近期新增`

- **显示开关** —— 可整体关闭悬浮球，不在任何页面出现。
- **默认吸附位置** —— 新打开页面时贴靠左侧或右侧，用户手动拖动过后以拖动结果为准。
- **禁用网址名单** —— 支持通配符规则，如 `*.example.com` 或 `example.com/admin/*`，命中规则的页面不渲染悬浮球。
- **规则可视化管理** —— 设置页内可直接增删改禁用规则，无需手动编辑配置文件。

## 04 视频双语字幕

四个平台各自适配了原生字幕获取方式，但共用同一套字幕面板交互与翻译队列。

| 平台 | 匹配范围 | 字幕来源 |
| --- | --- | --- |
| **YouTube** | `www.youtube.com/*` | 拦截播放器原生字幕轨数据，播放器控制栏内注入独立开关按钮 |
| **TED** | `www.ted.com/*` | 解析页面演讲元数据 + VTT 字幕文件 |
| **哔哩哔哩** | `www.bilibili.com/video/*` | 读取视频转录稿，识别分 P 切换避免重复请求 |
| **Coursera** | `www.coursera.org/learn/*` | 课程转录稿 |

字幕文本按句子分组后批量提交翻译队列（去重、分批、节流、失败重试）。字幕面板参照各平台原生设置菜单的视觉风格就地弹出，提供以下控制：

- **总开关** —— 一键启停当前视频的双语字幕
- **目标语言** —— 二级列表选择
- **字幕模式** —— 双语对照 / 仅译文 / 仅原文
- **翻译引擎** —— 按服务商分组的二级列表，与其他入口共享同一份引擎配置
- **背景透明度** —— 0–100 连续滑杆，实时调整字幕底板的深色透明度

面板会明确提示三种非就绪状态：检测中、未检测到字幕、翻译引擎未配置，避免用户面对空白无所适从。设置页「常规」标签中，每个平台各有两个独立开关——是否显示字幕入口按钮、以及双语字幕是否处于生效状态——并提供一个总开关同时控制全部四个平台。

## 05 PDF 与文档翻译

同一个阅读器页面承载五种文档格式，核心是一套完全本地运行、不依赖任何云端 OCR 或版式分析服务的 PDF 版式还原算法。

### PDF 双语对照阅读

基于 `pdfjs-dist` 解析，左栏用原生 canvas 还原版式，右栏脱离原版式重新排版展示译文，两栏各自独立触发翻译、互不联动滚动；支持双页对照与单页仅译文两种页面模式。

版式解析会把提取出的文字碎片按阅读顺序重排（PDF 内容流顺序并不等于视觉顺序），再聚类识别出六类内容块：

- **标题** —— 段落字号超过本页正文中位数字号的 1.3 倍即判定为标题。
- **列表** —— 识别显式项目符号 / 编号，也识别无符号但缩进明显深于正文、且连续两行以上的隐式列表。
- **代码块** —— 综合缩进差异、字体差异与连续行数（≥3 行）判定，能处理跨语言注释混排等边缘情况。
- **表格** —— 优先解析真实边框线，无边框线时按连续 ≥3 行且列位置高度一致的几何特征猜测表格结构。
- **图片** —— 只展示不翻译，单独裁剪渲染对应区域。
- **扫描件检测** —— 识别整页无可提取文字的扫描版 / 图片型 PDF，跳过翻译并给出提示，不会尝试也不会误报翻译成功。

### Markdown / TXT / SRT / HTML

- **Markdown / TXT** —— 统一走同一套渲染管线，整篇一次性提交翻译，无「分页」概念；TXT 额外保留原始空白与换行格式。
- **SRT 字幕文件** —— 只翻译文本行，序号与时间轴原样保留，避免破坏字幕文件结构。
- **HTML** —— 按文件声明编码自行解码（不强制当作 UTF-8，兼容 GBK / Big5 等常见编码），除正文外还能识别并翻译页面标题、页面描述、Open Graph 标题与描述等元数据字段。

> **统一的翻译队列**
> 五种文档格式共用同一套队列机制：单批最多 20 条 / 1200 字符，请求间隔 150ms 节流（跨批次全局共享），失败最多重试 3 次并按尝试次数指数退避；已译 / 失败 / 待处理状态全程去重缓存，切换目标语言或引擎会让旧缓存失效并重新提交。

所有格式的引擎与目标语言选择器统一在页面顶部，若尚未配置任何翻译引擎，会显示警告条并提供「前往设置」的直达入口。

## 06 设置中心

独立的设置页（`options.html`）按路由拆成四块：常规、引擎与翻译、用量、关于。

### 常规

- **基础行为** —— 界面显示语言、划词翻译总开关、剪贴板内容检测开关。
- **字幕** —— 双语字幕总开关，及 YouTube / TED / Bilibili / Coursera 四个平台各自的启停项。
- **学习与数据** —— 历史记录自动清理周期（1 / 3 / 5 / 7 天或不自动清理）、每日复习提醒开关与时间。
- **外观与重置** —— 主题模式（跟随系统 / 浅色 / 深色）；「恢复默认设置」需二次确认，只重置本页涉及的字段。

### 用量与成本仪表盘 `近期重构`

## 07 数据与隐私

LingVa 没有自建后端，本地数据都落在浏览器的 IndexedDB 与 `chrome.storage` 里。

| 存储对象 | 位置 | 关键字段 |
| --- | --- | --- |
| **生词本** | IndexedDB · `words` | 原词、译词、词性、音标、释义、例句、来源网址与上下文、收藏时间、掌握等级、复习次数、间隔天数、易记因子、状态 |
| **翻译历史** | IndexedDB · `history`（按时间戳建索引） | 原文、译文、语言对、引擎名快照、是否收藏、时间戳 |
| **用量统计** | IndexedDB · `usage_daily`（按天一条） | 使用次数、按场景 / 引擎 / 模型分桶的请求数、字符数、token 数与花费 |
| **设置项 / 密钥** | `chrome.storage.local` | 各引擎凭证、界面偏好、悬浮球位置、最近语言等 |

- **API 密钥**：仅保存在本机 `chrome.storage.local`，不经过任何中间服务器。
- **翻译文本**：由浏览器直接发送给用户自己配置的翻译引擎，LingVa 不设代理、不经手内容。
- **翻译历史 / 生词本**：仅保存在本机浏览器的 IndexedDB 中。
- **使用行为**：不上传、无埋点；用量仪表盘展示的所有统计数据都只在本机计算与存储，清除浏览器数据会导致这部分统计信息一并丢失。

历史记录的自动清理基于每 24 小时执行一次的后台闹钟，按时间索引游标扫描删除超出保留天数且未被收藏的记录，收藏记录永久豁免、不受自动清理影响。
